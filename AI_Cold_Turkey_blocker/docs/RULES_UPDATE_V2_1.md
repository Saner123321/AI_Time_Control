# 规则更新 v2.1：更新器修复

适用于已回传的 VMware 安装 `AICT-Beta-111e0fe3cfa348b4a055eafb99e25f06`。沿用 v2 的规则逻辑和程序文件，只修正更新器；不是新的封锁实验，不需重新建规则。

## 本次失败原因

v2 在暂停后台后替换浏览器桥接配置时，Windows PowerShell 5.1 将空的备份路径转换成了非法路径。尚未进入新版文件复制阶段。恢复流程又无条件覆盖未改动的文件，被仍运行的采集程序占用阻断，未能确认旧后台恢复。附带状态文件是快照，不能证明当前后台仍在运行。

v2.1 改用明确的同目录备份文件，并在停止后台之前实际检查创建/替换操作。更新步骤逐项记录；恢复只处理实际尝试改动的文件，未改动的程序不覆盖。一个桥接或任务恢复错误不会阻断对完整旧后台的恢复尝试；若程序文件未能恢复完整，则保留限制并报告，不启动混合版本。

## 操作

1. 关闭旧更新窗口及“专注计划”主窗口，保存浏览器内的工作。
2. 将 `AICT-beta-rules-update-v2.1.zip` 复制到同一虚拟机，完整解压到**新文件夹**。
3. 双击 **更新专注计划.exe**，点击“更新并保留规则”，完成管理员确认，等窗口显示结果。
4. 成功后仍从原桌面“专注计划”打开。浏览器扩展不用重装；无需恢复快照、卸载或清空数据库。后台停止的现有安装也可以继续。
5. 若失败，回传这个新文件夹中的 `update-result.json`；同时生成的 `service-status-after-update.json` / `service-fault-after-update.json` 一起回传即可。新报告包含失败阶段、实际改动清单和分别记录的恢复结果。

原规则更新逻辑：收紧立即生效；包含放宽才等待，旧规则在等待期间继续运行，到期自动切换；界面分“正在生效 / 待生效”。详见包内 `规则交互说明.md`。

本地在实际 Windows PowerShell 5.1 中完成原始空备份错误复现、真实文件替换、锁占用、选择性恢复及数据保持等 8 项测试。服务和计划任务操作在这些本地文件测试中使用替代对象，未修改主机服务；实际虚拟机更新与恢复仍待此次确认。
