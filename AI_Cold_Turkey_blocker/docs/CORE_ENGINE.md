# 规则与存储内核：首个独立开发增量

2026-11-02：阶段0的平台整体验收仍未通过。AppLocker 身份/时延、短时WFP和服务自身生命周期已有独立来宾证据，
首个增量实现不调用系统封锁接口的规则、额度、锁定和SQLite存储。后续已增加独立WPF/后台开发预览，参见 `DESKTOP_PREVIEW.md`；仍没有正式Windows服务或主机安装入口。
不将本增量标记为阶段0/阶段1整体完成；原有平台门槛和原始证据保持不变。

## 当前实现

- `src/Aict.Core`：每周半开时间段、跨午夜与周切换；固定起点的封锁/休息循环；应用和域名的黑/白名单匹配及组内例外。
- 每组共享每日额度；同一前台时间同时命中应用和网站只扣一次；不同规则组分别计量，任一组仍拒绝就继续拒绝。
- 硬时段/循环独立于剩余额度。可信系统必需应用集合由后端提供，应用豁免不会连带豁免网站维度。
- 精确划分跨午夜使用；区分空闲阈值的有效部分；锁屏、已知睡眠、后台不计量；重复/重叠区间不重复收费。
- 缺失观察记录为 `HasGap`，保留已知时长，余额未知且受限；恢复遥测不自动清除当天缺口。不会把缺失当作精确的零使用。
- 修改提交时冻结完整目标JSON和摘要；当前规则的延迟决定本次等待，不能先等满再替换目标或缩短自己的等待。
- 等待结束后仍按旧规则判断时段/循环/额度锁；可撤销待生效修改，原规则保留，重新提交重新计时。
- 导入/关闭计划可经同一完整配置提交；卸载意图走同一队列，条件满足仅返回授权结果，不执行系统卸载。
- 时间由运行期单调计时推进，系统时间只用于异常诊断；小步反复改时间不会加速等待，异常前后跳不直接清零额度或解锁。
- `src/Aict.Storage`：带修订号和摘要的SQLite状态快照，WAL＋FULL同步、事务、乐观并发控制；拒绝已有文件初始化、未知架构、缺行、损坏摘要和负使用量。
- 缓存中的有效状态也不能静默覆盖后来损坏的原数据库。回滚和并发写入已经过自动测试；没有做实际断电证明。
- 当前额度记录可输出CSV，完整快照可输出JSON；CSV名称转义并防公式注入，保留缺失标记。不是完整的应用/事件日志产品。

## 关键语义与接口边界

首批日历支持上海（`Asia/Shanghai`／`China Standard Time`）和UTC；其他时区明确拒绝，不冒称已经覆盖DST和所有地区。
域名规则包含根域及子域，识别IDNA、大小写和末尾点，拒绝scheme、路径、通配符及查询参数。精确URL过滤留给浏览器层。
应用ID是后端将来提供的发布者/哈希身份键，当前示例的 `demo.video` 是模拟标识，不是进程名封锁实现。

`UsageSlice` 必须由后端合并后的有序前台观察产生；同一时间区间的应用和网站信息要合成一个上下文。
空闲期间不应把一次长时间观察当作持续输入；输入/前台变化应切分区间。失联标记来自后端健康状态，不能由UI自报可信。
已知锁屏/睡眠长区间不计量；已知前台超过五分钟却没有分段的观察按缺口处理，单个区间上限31天，避免无界输入。

`EngineSnapshot`、`ClockReading.Trusted`、`PendingChange` 和数据库路径都是**可信后端内部输入**。
未来命名管道不得接受客户端整份状态、修改后的额度、已等待时间或可信时间布尔值。UI仅能提交目标规则和查询状态。
`ChangeQueue.TryApply` 是给定时刻的判断，还没有实现任意计划的下一解锁窗口搜索器或后台两秒调度器。

重开数据库保留额度、循环起点、冻结修改及截止信息，但主动把保存的时钟可信标记降为未核验。
重新建立可信时间锚必须由后端完成，并且不能降低已有时间高水位；未核验时只允许保存草稿，不能回填一个早提交时间。
**可信时间源和离线/重启核对流程尚未接入**；没有凭保存的 `Trusted=true` 宣称时钟安全问题已解决。

数据库路径由后端选择；正式安装时目录需要独立权限和IPC查询，不能把开发用路径接口暴露给普通权限客户端。
快照摘要用于完整性检测，不是抵抗管理员修改的认证签名。没有自动覆盖/清空损坏数据库的恢复动作。

当前49项.NET测试全部通过；现有47项Python证据/门槛回归独立保留，不拿这些单元测试替代Windows机制实测。

示例输出包括 `combination-lock.json`、`state.json`、`usage.csv`。组合锁示例验证：
