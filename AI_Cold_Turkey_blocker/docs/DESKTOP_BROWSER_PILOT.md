# 正常入口与下一步网站测试

这次不重新安装应用后台，也不重置旧规则。新包只提供明确的正常入口，并开始浏览器原生策略的隔离试验。

## 双击即可

把 `AICT-desktop-browser-v1.zip` 复制到原 Windows 11 虚拟机，解压，双击根目录的 **专注计划.exe**。
无需命令行，无需管理员启动，无需恢复快照或重跑应用实验。
入口会在当前用户目录保存自己的副本，并在虚拟机桌面创建 **专注计划（测试版）** 快捷方式。
以后双击该快捷方式。新包不包含开发预览入口，不必再找旧包 App 目录中的 EXE。

“我的应用规则”会列出当前用户原有测试会话，点击“打开我的规则”时附带正确连接信息，连接原来受保护的界面与服务。
不会安装、启动、停止或重置服务，不创建另一份空白规则库。启动前核对旧界面的冻结文件哈希。
旧测试包有60分钟自动结束机制；后台已经停止时，入口仍显示最后保留的规则记录，明确标注历史状态，不冒充实时封锁。
多个会话可下拉选择；不默默切换到另一份配置。

## 网站测试全程点击

1. 点 **下一步：网站测试**，选择虚拟机已安装的 Edge 或 Chrome。不自动安装浏览器。
2. 点 **1. 开始网站测试**。本轮只临时封锁 `example.com`，不修改其他网站，不修改浏览器账号、插件或浏览记录。
3. 策略页打开后点浏览器自己的 **重新加载策略**，确认 `URLBlocklist` 中有 `example.com`，状态正常。
4. 点 **3. 访问测试网站**。新导航应出现明确的管理员封锁提示；只出现网络错误不能算通过。必要时刷新已打开的测试页。
5. 下拉选择实际观察结果；点 **导出诊断**，选择桌面，把生成的 `desktop-browser-时间戳` 文件夹复制回项目 reports 并提供路径。
6. 点 **恢复本次网站测试**；在策略页重新加载，再访问 example.com，确认网站访问恢复。可再次导出收尾诊断。

如果同时测两种浏览器，每种各自导出一次，避免把一个浏览器的观察当成另一个的结果。
恢复和导出都在界面，不需要 PowerShell。退出入口本身不会删除策略。
本轮先验证浏览器原生策略，不需要安装插件，不能据此宣称扩展部署或完整防绕过已完成。

## 边界和恢复

- 所有正常入口和浏览器策略操作只允许 VMware 来宾，物理主机会在任何写入前拒绝。
- 网站操作只写当前用户的 Edge/Chrome URLBlocklist；不写 HKLM，不要求管理员，不影响其他 Windows 用户。
- 发现已有网站允许/封锁策略时拒绝叠加，避免优先级冲突或把旧限制误认为本次效果；不清空旧列表或覆盖条目。
- 先保存恢复记录、创建当前用户级15分钟恢复任务并核对任务，再写入自己的条目。恢复仅删除编号、类型、内容均符合记录的自有值；外部改动会报错并保留。
- 任务在当前用户已登录时运行，休眠/关机/注销或任务故障可能延迟；不靠它来证明任何故障下都恢复。遇到问题重开桌面入口，点恢复并导出诊断，不删除用户目录或系统策略。
- 本轮仅验证固定测试域名；网站规则尚未接入应用服务的时段、锁定、白名单、额度，也未处理已有页面的脚本动态更新。测试恢复按钮不是产品正常解锁入口。
- 浏览器注册表读回只表示策略已发布。必须在浏览器策略页确认策略被接受、在网站导航确认实际拒绝，界面不会把写入成功算成封锁成功。
- Edge 官方说明此策略不适用于登录个人微软账号的配置文件。遇到“不适用/无效”按实际结果导出，不为试验删除或改动账号。Chrome/多配置文件同样须实测。
- 原生网站策略独立于插件；移除插件不会直接删除原生策略，但尚不能外推为配额、全部浏览器模式、任意网站与绕过方法都得到保护。
