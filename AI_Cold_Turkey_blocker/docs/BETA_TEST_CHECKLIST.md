# 专注计划：集中测试清单

本轮用一个完整安装包测试；无需命令行、重启或恢复快照。先保存工作，使用 1—3 分钟短规则。安装前的快照仍作为独立故障恢复基线。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1. 安装与入口 | 完整解压，双击根目录“专注计划.exe”，安装；随后从桌面“专注计划”打开 | 进入同一份规则。后台显示已连接、应用策略已确认、采集正常；旧数据存在时说明迁移结果 |
| 2. 浏览器连接 | 用“浏览器设置”指引，在日常使用的 Edge / Chrome 配置文件加载组件，刷新状态 | 配置文件连接数增加。启用网站规则前完成此步 |
| 3. 自定义网站 | 新建仅网站规则，填写你想封锁的域名，启用 2 分钟倒计时；关闭默认循环，暂不勾锁定 | 目标域名及子域名拒绝；无关网站正常；已有目标标签页出现封锁页；倒计时后恢复 |
| 4. 应用身份 | 选择包内 `Targets/Target.exe`，测试短时封锁；再试 `Targets/Renamed.exe`、`MovedTarget.exe` 和 `Targets/AllowedControl.exe` | 前三个内容相同，均拒绝；内容不同的对照允许。然后选一个自己的非系统 EXE 验证 |
| 5. 持续执行 | 生效时关闭界面再从桌面打开；在任务管理器结束 `Aict.Beta.Agent.exe` | 关闭界面不解除规则；采集失联可见，后台尝试恢复。普通权限停止服务应拒绝；提权结果请单独说明 |
| 6. 移除组件 | 网站规则生效时停用或移除浏览器组件；之后重新加载 | 浏览器联网被限制，失联持续后关闭一次窗口；重新加载并确认规则后恢复。记录旧标签页、IPv6/QUIC 是否有异常 |
| 7. 日程和循环 | 分别测试短循环、当前时段及跨午夜计划的预览/保存，关闭无关条件 | 同一循环重开界面不重置；不在封锁条件内时允许。跨午夜实际边界未等到请写未测 |
| 8. 额度和统计 | 单独启用 1 分钟额度，关闭全天/循环/时段等硬封锁；实际前台使用目标，再空闲/锁屏 | 消耗与前台使用一致，耗尽后拒绝；空闲 60 秒后停止计入。应用和网站同时命中同组不重复扣；统计可刷新/导出 |
| 9. 白名单与例外 | 先仅测网站白名单及子域名例外；应用白名单另建很短倒计时并先保存工作 | 只允许所列域名/应用及必要系统项；组内例外不解除其他规则组的拒绝。应用白名单可能关闭其他非系统程序 |
| 10. 锁定与修改 | 设置短封锁/休息循环、封锁期间锁定和 1 分钟修改延迟；提交停用或改时段 | 显示整份冻结修改；等待结束且旧规则允许修改才生效。重开界面仍存在；不能临时替换已经等待的内容 |
| 11. 卸载与导出 | 先图形导出，再在锁定期申请正常卸载 | 卸载服从同一等待/锁定条件；批准后仅清理本软件限制。下次打开浏览器组件应自行清理并卸载；保留历史数据 |
| 12. 故障恢复 | 仅误封或无法正常收尾时运行独立管理员恢复工具 | 输入短语及管理员确认后恢复；出现错误则保留文件，不删数据库 |

每项记“通过 / 失败 / 未测”，并写实际现象。程序启动时 Windows 提示“系统管理员已阻止”属于 AppLocker 正常拒绝表现。网络错误本身不能证明域名封锁正确，需要同时验证无关网站可用及界面组件状态。

给开发者回传：图形导出的 `aict-beta-时间戳` 文件夹；如果安装就失败，先回传解压目录的 `setup-result.json` 和提示截图。无需再次运行旧实验脚本。
