# 网络保护修复 v13

## 为什么未封锁的网站也会报网络访问被拒绝

网站封锁有两层：插件判断具体网址；Windows网络兜底在插件保护未确认时限制整个受管浏览器。因此整浏览器兜底被触发时，正常网站也可能显示 `ERR_NETWORK_ACCESS_DENIED`。

旧版把3500毫秒心跳新鲜度和前台窗口标记直接用于网络开关。窗口切换、采集延迟或睡眠恢复可能使标记短暂不同步。本机日志证实出现过Edge整浏览器保护触发，但旧版只有聚合状态，不能把用户每次页面报错都精确对应到某次触发，也不能排除其他防火墙或VPN造成同类错误。

## 本次调整

- 网络就绪和前台使用统计分开判断。已确认当前计划的组件有最多5秒清醒时间的连接租约，轮询本身不会续期；前台标记短暂不同步最多缓冲2秒。新计划、明确失败的确认不借用旧计划租约。未确认的新配置文件不能凭后台组件一直放行。
- 睡眠不消耗这份连接租约；恢复后若计划改变，仍须确认新计划。使用额度继续沿用已批准的“统计缺口按时长计入额度”，不把网络缓冲当成已知使用记录。
- 插件收到窗口/标签切换事件立即发送状态；原生通信超过6秒未返回时断开并重连，旧连接的回复不能确认新连接。
- WFP仅在自有过滤规则确有变化时提交修改；未变化仍读取并验证规则，不再每半秒提交空事务。保留按浏览器程序和指定用户的IPv4/IPv6范围，不改其他软件的网络规则。
- 状态与日志分别记录Edge/Chrome是否实际限制、原因和切换。查询或修改失败时显示未确认，不能把期望状态当作已执行。
- 组件0.5.0只为主页面的此类错误提供一次自动重试：要求后台确认本软件的一次限制已解除、错误发生在该区间内、当前规则允许该网址、用户尚未切换页面。错误网址只在内存中短暂保留。不循环刷新，不刷新封锁目标或其他网络错误。新权限 `webNavigation` 用于接收错误和完成事件。

真正移除插件或持续失联时仍会启用网络兜底；这次减少瞬间误触发，不承诺在所有故障下始终联网。窗口前台标记持续冲突仍须保护。后台服务停止等情况也不能靠插件自行解除持久过滤。

## 怎么更新

适用于当前已安装v12的本机安装；更新器核验完整基线，不匹配则停止。

1. 右键右下角“专注计划”图标，选择“退出界面”。仅点主窗口叉号会隐藏，不能满足更新要求。
2. 双击本目录 **更新网络保护.exe**，点击“更新并继续使用”，完成Windows管理员确认。
3. 在Edge扩展管理页 `edge://extensions`，对安装目录中的“专注计划”组件点击重新加载，确认版本 **0.5.0**。Chrome使用 `chrome://extensions` 做相同操作。若原来从旧解压目录加载，使用更新窗口“复制新版浏览器组件路径”改从安装目录加载。组件新增权限可能需要浏览器确认。
4. 已经停留在网络错误页的标签请手动刷新一次。重载之前产生的错误没有事件记录，不能自动恢复。

保留规则、例外、已用额度、历史与待生效申请；保持持续使用，不替换数据库、不退还历史扣时、不添加短测截止时间。托盘关闭和重新唤回行为保留。退出界面不会停止后台服务和采集。

本次开发不操作用户当前浏览器、不安装更新，也不关闭系统防火墙。实际主机升级和前台使用验收由用户操作。

## 验证范围

本地验证包括186项核心测试（含就绪缓冲、到期、错误确认、新计划及睡眠时钟边界）、27项组件测试（含有限重试与原生连接看门狗）、桌面及托盘生命周期自测、14项持续运行/计时器检查和8项更新文件恢复检查。回执在本机 `reports/network-v13-local-checks-20261105.json`。

Edge、Chrome各22项隔离检查通过，使用真实浏览器与内存页面，含一次错误页恢复验证。CDP的AccessDenied会产生另一错误码，因此网络拒绝信号和本产品限制解除状态为明确的测试注入；没有改系统网络过滤。真实回环网络的一轮被旧版保护中断，保留失败记录、不计通过。详细证据见本地回执。隔离浏览器测试不等于在用户当前浏览器实际启用WFP的误断网问题已获得长期验证。后续可从导出诊断中查看 `BrowserNetworkGateChanged` 的浏览器和原因，结合采集诊断核对；个人证据不上传仓库。
