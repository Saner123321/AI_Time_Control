# 已批准架构与阶段门槛

**2026-11-04 持续使用 v10：** 主机安装默认 `continuousUse=true`、`hostTrialEndsUtc=null`，显式持续模式与有限截止时间互斥。服务/代理/原生桥都验证安装模式，普通规则接口不能切换。迁移保留原数据库，先暂停自有旧到期任务，健康确认后撤销；持续模式下即使旧安全命令被调用也不会清理策略。新安装的短测可选；修复保留原模式，后续正常更新不得重新加入统一截止时间。详见 `CONTINUOUS_USE_V10.md`。


**2026-11-03 网页加载优化 v9：** 组件0.4.0只为潜在拒绝目标生成导航中转规则；白名单和超限/不支持表达式保留全导航守卫。直接放行规则仅在所有当前规则都能证明候选范围允许时生成，作用仅限页面导航，不放行整个标签页的后续请求。复杂组合回退确认页及精确临时通行。写入前验证浏览器正则支持，跳过不可用的可选优化；必需守卫不受支持时不确认计划。规则读回未变化不重复写入。下方v8全导航中转描述为历史行为，详见 `SMOOTH_NAVIGATION_V9.md`。


**2026-11-03 原因显示 v8：** `BlockExplanations` 从实际规则引擎原因生成稳定说明，按当前时区显示固定截止时间，不使用每秒变化的倒计时字符串作浏览器计划指纹。网站计划带规则名称和说明，组件先按完整网址筛选真正拒绝的组，再以纯文本渲染原因。单纯域名的页面导航也走本机确认页，域名子资源规则继续保留。桌面状态包含各当前激活规则的说明。未知/断连状态清除旧说明并提示未确认；Windows自带拒绝对话框不替换。详见 `BLOCK_REASONS_V8.md`。

**2026-11-03 分段独立额度 v7：** 可选 `QuotaSlots` 存储1—24个拥有稳定身份、起止分钟、独立限额和名称的时段，与旧单份 `DailyQuota` 模式互斥。每天循环区间不得重叠，允许相邻与跨午夜。用量沿用原存储键 `group/date` 并增加可选 `group/date/slot`，旧快照无需重写。计时、缺口、状态和计划统一按各 `QuotaSpec` 求交；各时段分别扣时，只有当前时段耗尽才触发本组封锁。旧每日/单时段默认不序列化新字段；新字段启用后由新版本读取，不支持直接降级。

时段身份保持稳定以保留计数；增加无交叠时段可证明更严格，移除、提额或无法证明的范围变化仍等待。旧单时段转换用确定身份继承对应原计数。改变或合并时段时按旧/新周期实际交叠汇集原计数，合并保留合计用量；不能从仅有周期累计精确拆分的跨午夜历史采用保守继承。已开始新版本写入后更新器不做旧程序降级回滚，维持既有恢复原则。参见 `MULTI_QUOTA_V7.md`。

**2026-11-03 时段额度 v6：** `DailyQuotaWindow` 为空时保持原每日额度；配置起止分钟后，仅在每天该区间计时及判定额度耗尽。跨午夜周期按起始日期使用原用量账户键，不在午夜重置。`QuotaPeriods` 统一生成实际区间，已知用量及未知缺口都按区间求交，状态、计划和导出采用同一周期。改变额度时段的包含关系保守等待；生效时通过 `CarryForward` 在旧/新周期账户间继承最大用量和缺口，不制造新额度。新字段默认不序列化，旧快照与待生效指纹保持兼容。详见 `WINDOW_QUOTA_V6.md`。

**2026-11-03 例外整理 v5：** 规则组可选保存 `websiteExceptionDetails`，未填写时不序列化，旧数据和待生效校验无需迁移。网址列表仍是唯一的例外匹配来源，备注和分组不参与浏览器计划指纹。独立 `UpdateWebsiteAnnotations` 请求只能为已有当前/待生效网址修改文字；事务内更新当前与待生效元数据和对应校验，保留原申请身份、范围及截止时间。搜索和分组只是界面视图，不作为解除封锁开关。参见 `EXCEPTION_ORGANIZER_V5.md`。

**2026-11-03主机范围变更：** 用户明确要求功能问题直接在主机测试，撤销仅VM的实施限制。新增独立 `HOST_TRIAL` 编译目标，原VM包不变。

## 当前集成实现

`Aict.Beta.Core` 统一决定应用计划、网站计划、共享额度和修改/卸载。`Aict.Beta.Service` 以 LocalSystem 运行，受管理用户的普通权限界面和 `Aict.Beta.Agent` 经有界、验证对端的本地管道访问；采集请求还验证客户端为受保护代理文件。
AppLocker 经已验证家庭版管理通道的独立 Framework/MI 桥执行，读回逐项对比服务计划；黑名单按文件哈希，应用白名单采用每组路径拒绝及文件哈希/必要系统路径例外，不使用会覆盖其他拒绝的全局允许。
浏览器组件使用 DNR 的组内排除，保持多组“任一拒绝即拒绝”。标准 Edge/Chrome 的失联回退使用 WFP ALE v4/v6、应用身份和用户安全描述符条件，独立 provider/sublayer，持久过滤；不以 hosts、IP映射或全局防火墙关闭作为域名主执行器。
浏览器注册和访客/无痕策略由 SYSTEM 在指定用户已加载的 HKU 配置中处理，已有冲突值拒绝覆盖。正式商店强制安装尚未完成，VM组件手动加载一次，失联不据此放行。
规则与额度事务快照、增量日统计同库分表；应用/网站统计为重叠维度，缺口单独保存。服务恢复、自动启动、权限收紧和持久过滤已实现，重启/断电/更新完整矩阵不据此视为通过。
正常卸载走规则队列，独立管理员故障恢复另设入口。清理仅撤销拥有的策略/任务/过滤/注册值，保留数据和惰性桥接，使关闭的浏览器配置下次启动时能清掉持久扩展规则；管理员最终控制的边界不变。

当前优先级：用户已明确暂无专业版环境，继续优先适配家庭版；不以升级主机或购买专业版作为前提。
专业版覆盖保持未测试，不从家庭版结果推断。既有失败和阶段门槛保留，后续按实际证据逐项更新。

## 规则语义固定值

- 上海时区、周计划与跨午夜；循环以持久化起点计算。
- 时段硬封锁优先于额度；组内例外不能解除其他组的拒绝。
- 每组共享前台使用额度；60 秒空闲、锁屏、关机、睡眠不计入；应用/网页重复命中只计一次。
- 时段锁与延迟锁可组合；默认延迟 24 小时；修改内容提交时冻结，重提重新计时。
- 额度每日零点重置且不结转。异常时间变化不自动解除锁定，不把遥测缺失记作零使用。
- UI、导入、更新、卸载和本地 API 共用服务端锁定检查。
- 90 天本地事件留存，默认只记录域名，CSV/JSON 导出。

## 隔离与所有权

- 保留现有账户结构；不承诺抵抗已提权管理员、安全模式、离线修改或重装。
- 安装服务和策略仅在实验来宾中进行；用户随后明确允许直接使用现有 Windows 11 VMware 来宾。第一次系统写入前必须建立并验证恢复快照，不将主机作为实验对象。
- AppLocker 修改必须带拥有者标记/规则 GUID 清单，并保留基线；不能卸载时整包覆盖既有策略。
- 若检测到非本产品策略变更，应停止自动恢复并报告冲突，避免覆盖其他管理工具的更新。
- 浏览器已有策略必须先比较；冲突不静默覆盖，不触碰用户浏览记录。
- WFP 使用独立 provider/sublayer 和持久对象清单；仅清理自身对象。动态会话退出即删除的过滤不能冒充持久防护。
- 服务保存的是状态与计算日程；AppLocker/WFP 保存的是执行策略。二者失败状态分开呈现。
- Native Messaging/命名管道对身份、长度与消息类型做验证，不接受任意文件路径写入和命令执行请求。

## 阶段 0 阻塞原则

缺少隔离来宾、管理员登录、管理入口或恢复证据时，记 `BLOCKED`/`NOT_RUN`，不记不支持，也不记通过。
检测脚本/门槛检查器的离线测试成功不等于封锁成功。实际 Windows 行为只能由来宾实测确认。
不得从 DLL 存在、HypervisorPresent 或安装注册记录推断功能有效。
# 网址模式扩展（2026-11-03）

见 `URL_PATTERNS_V4.md`。纯域名策略维持既有 DNR 过滤；含路径/通配符的计划由 DNR 将 HTTP(S) 主/子页面导航重定向至组件本地确认页，统一计算所有规则组后，仅对明确允许的精确 URL 和标签页发放会话通行。计划变化先清除旧通行，规则写入及读回成功后才确认计划；旧版本组件不能确认此类计划。该模式不承诺阻止所有后台子资源或撤回已缓冲媒体。

后台临时接收完整 URL 以准确扣除额度，统计仍只落地域名。页面规则忽略查询与片段；通配符对完整 HTTP(S) URL 进行大小写不敏感匹配。模式包含关系采用保守的集合证明，无法证明仅收紧则等待。主机更新保留数据库及待生效申请，并通过明确的更新按钮重新安排短期测试截止和原独立安全任务。
