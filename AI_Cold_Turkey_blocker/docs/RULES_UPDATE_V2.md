# 规则交互更新 v2

**更新入口已修正为 v2.1：** 旧 v2 更新器回传失败，现使用 `AICT-beta-rules-update-v2.1.zip`。规则语义及程序文件不变；安装步骤与故障修复说明见 `RULES_UPDATE_V2_1.md`。下文保留原始 v2 设计记录。

本更新覆盖旧文档中“所有修改都延迟”和“延迟结束还需等待旧规则休息窗口”的描述。适用于此次已安装、已回传日志的 VMware 自用测试版，不安装到物理主机。

## 现在的规则

1. 只收紧或不影响限制的修改立即保存执行：新增封锁对象/规则、减少额度、删除有效例外、缩小白名单、扩大每周封锁时段、延长倒计时，以及单纯改名。界面仍分别显示已保存与实际执行读回状态。
2. 包含放宽的修改需要等待：移除封锁对象、增加有效例外、增加额度、扩大白名单、缩短时段、停用/删除规则、缩短修改等待时间。等待时旧规则完整运行，到指定时间自动更换，不再被旧封锁时段额外拖后。
3. 既有收紧又有放宽的整份修改，或无法证明未来所有时刻都仅收紧的复杂修改，按包含放宽处理。例如改变循环周期会改变未来的休息位置，不能只比较封锁分钟数或封锁比例。当前支持同一起点、同一总周期内缩短休息，作为可证明的收紧。
4. 提交的完整内容固定。再次提交相同内容保留原时间；换成不同待生效内容重新等待。取消申请只保留旧规则。已有申请时从“正在生效”视图提交仅收紧的新配置，会立即应用并取消原申请，避免旧申请以后覆盖新限制；确认框会说明。
5. 现有待生效申请升级后保留原内容和截止时间，并采用到期自动切换。正常卸载仍按放宽申请处理。系统时间异常或存储故障不会自动绕过保护。

## 界面

左侧有“正在生效”和“待生效”两个视图。提交放宽修改后自动展示待生效规则，包括新名称、目标、例外和日程；上方显示剩余等待时间及切换时间。可以切回查看当前实际执行的旧规则。

到期由后台自动切换，无需保持界面打开。正在查看待生效规则时，到期会回到当前规则。可以编辑待生效配置，但不同内容重新提交会重新计时，不会临时替换已经等完的内容。

旧的“封锁时锁住修改”控件不再作为额外等待窗口显示；历史字段保留用于兼容。放宽规则统一由当前生效配置中的等待时间保护，不因旧字段未勾选而跳过等待。等待时间减少本身也走原等待时长。

## 使用更新包

1. 在虚拟机保存工作并关闭“专注计划”主窗口，浏览器组件继续保留。
2. 将 `AICT-beta-rules-update-v2.zip` 完整解压到新文件夹，双击“更新专注计划.exe”，点击“更新并保留规则”，完成管理员确认。
3. 等待结果；更新会短暂重启专注计划后台和采集组件，浏览器联网保护暂时保持限制，连接恢复后恢复正常。无需恢复快照、卸载、重新创建规则或重新加载浏览器扩展。
4. 成功后仍使用原桌面快捷方式。建议先用 1 分钟等待验证：新增封锁域名立即生效；再给它加例外，应看到旧规则仍运行、新规则已展示、到期自动切换。
5. 失败时回传更新文件夹的 `update-result.json`；若同时生成 `service-status-after-update.json` / `service-fault-after-update.json`，一起回传。不要删除原数据库。

更新只接收此版原始安装的固定文件集合，先核对安装来源、权限和文件哈希，备份将替换的程序文件，不替换规则数据库。新服务启动前的复制失败会尝试恢复旧程序；新服务启动后的失败保留新程序与数据以供诊断，不自动倒退数据库。断电中断等完整升级故障矩阵仍未验收。

本地规则测试与界面检查通过不等于虚拟机更新/执行已通过。本轮来宾更新结果待回传。
