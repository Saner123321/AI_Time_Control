# 家庭版优先的当前进度与交付估算

截至 2026-11-02，已有可审计的两项底层证据：

- 家庭中文版 25H2 / 26200.7840 上，48 次受控回环通信验证 WFP 对指定实验 EXE 的 IPv4/IPv6、TCP/UDP 临时阻断和清理。
- 同一来宾上，公开 Windows MI / AppLocker CSP 的 AuditOnly 创建、读回和删除通过，相关任务与分组清理通过。

尚无完整产品：规则引擎、额度与锁定状态机、WPF 界面、正式后台服务、浏览器扩展、安装更新卸载和长期故障验证还未完成。
实际 Enforce 启动阻断、重启持久化和任务管理器防绕过均不能以管理接口通过代替。

## 剩余人工配合

估算从当前进度开始：底层验证约还需 2–4 轮批量实验；到可用自用版预计合计还需用户配合约 6–10 轮。
这些轮数包含底层验证，不是相加。单轮覆盖多项测试；新失败可能增加针对性的复测，不能保证固定次数。

优先合并为以下批次，每一批可能需要一次修正复测：

1. 应用真实启动阻断、身份匹配、例外、已运行程序、独立策略清理。
2. 服务权限、异常退出、重启/睡眠、时间与额度持久化、故障恢复。
3. 浏览器网站规则、扩展失联、IPv4/IPv6 网络兜底与持久过滤。
4. 产品安装/卸载/更新、跨组件完整回归，以及短期真实使用验收。

不再为每个小修改要求用户手工复制一包。统一测试入口自动运行多项、打包日志、显示清理状态；
人工主要负责虚拟机登录、必要的管理员确认、重启和阶段验收。此前编码/日志导致的可避免返工不计作必要平台验证。

## 工期范围

按连续开发及及时配合验收的工作量估算，从现在起：

| 交付层级 | 范围 | 估算 |
|---|---|---|
| 可用原型 | 界面、基本周计划、应用封锁、锁定/延迟修改、状态显示 | 5–10 个有效开发日 |
| 核心功能自用测试版 | 用户六项核心需求，含网站/额度/记录导出/重启与卸载保护，并完成基本故障验证 | 4–8 周 |
| 长期可靠版本 | 长期试运行、兼容更新、更多故障场景、正式分发与恢复流程 | 2–3 个月或更长 |

这是粗估工作量，不是确定完成日期。日历进度取决于连续开发时间、用户配合重启/验收的节奏和新故障。
浏览器扩展商店发布与审核单列为外部依赖，不保证审核时间；正式防停用承诺以实际商店部署验证为准。
不能承诺抵抗已提权管理员，也不把“关闭界面后仍工作”当作完整防篡改证明。

下一明确里程碑是一次合并的真实应用阻断与恢复实验，而不是继续只做入口清点。
