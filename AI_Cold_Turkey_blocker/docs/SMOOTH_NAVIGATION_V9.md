# 网页加载优化 v9

修正旧组件把所有网站先跳转到本地确认页造成的闪屏。浏览器组件版本为 **0.4.0**，后台程序沿用 v8。

- 与黑名单无关的网址直接加载。
- 页面、域名和常见通配符例外，经所有当前规则共同确认允许后，直接加载，无需经过插件确认页。
- 多组规则仍然共同生效；一组例外不能覆盖另一组封锁。白名单只提前放行能够确认属于共同允许范围的网址。
- 无法提前证明安全的复杂组合继续进入本地确认页。快速确认放行时隐藏中转卡片，不再先显示“已允许”再跳转；确认较慢时才显示状态。页面配色跟随系统深浅色设置。
- 每五秒的规则读回保留，但内容不变时不重复写入。规则变更仍撤销旧临时通行；封锁页原因显示保留。

这减少常用访问路径的中转，不承诺所有复杂网址或浏览器自身加载背景都完全没有闪烁。

## 更新

关闭专注计划主窗口，双击本文件夹 **更新网页加载优化.exe**，按“更新并开始30分钟测试”完成更新。适用于已经安装 v8 的主机测试版，保留规则、例外备注、额度和待生效申请；继续沿用30分钟测试及独立恢复任务。

随后在浏览器扩展管理页面重新加载“专注计划”到 **0.4.0**，再刷新已打开的网页。使用更新窗口提供的安装目录组件路径；若旧组件加载自旧解压包，改为加载安装目录的组件。更新不会代替这一步。

## 验证

运行 `node --test tests/extension-*.test.mjs` 检查规则组合、端口、路径、查询参数、例外交集、规则撤销、浏览器不支持正则时的保守回退、未变化规则不重复写入，以及确认页快速放行不显示卡片。

运行 `node tests/extension-live.mjs` 和 `node tests/extension-live.mjs --chrome`，使用独立无个人数据浏览器配置及本机测试服务器，记录真实导航链，检查普通网址和例外无插件中转、被封锁网址未到达服务器、规则释放和多组规则冲突。脚本不会操作用户现有浏览器窗口或修改 Windows 策略。本机已有网络限制可能阻断测试服务器连接，出现这种情况需保留失败结果，不能算测试通过。

本地构建及实测回执位于 `reports/smooth-navigation-v9-local-checks-20261103.json`，不上传个人日志。更新器继续接受8项文件替换/恢复测试，不替换数据库。
