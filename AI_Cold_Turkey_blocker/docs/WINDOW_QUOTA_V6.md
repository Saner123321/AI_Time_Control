# 指定时段的共享额度 v6

先在旧窗口提交想保留的草稿，再关闭专注计划主窗口。双击本文件夹 **更新时段额度.exe**，点击 **更新并开始30分钟测试**，完成管理员确认。更新保留数据库、规则、例外备注、用量和待生效申请；已停用的规则保持停用。浏览器组件不变，无需重载。本轮不自动应用到主机，安装由用户进行。

## 设置方法

1. 在规则编辑的“何时限制”里勾选 **启用共享额度**，输入分钟数。
2. “额度范围”可以选 **全天（每日零点重置）** 或 **每日指定时间段**。
3. 选择指定时段后填写开始、结束，例如 **18:00 至 22:00，共用30分钟**。
4. 点击 **提交完整修改**。现有规则放宽或无法证明仅收紧的变动，仍按当前等待时间生效；旧规则继续执行。

示例：每天18:00—22:00，B站使用20分钟、YouTube使用10分钟，共用30分钟耗尽，此组目标封锁到22:00。18:00之前和22:00之后，这份额度不计时、不触发封锁。多个应用/网站共用一组额度，同一秒最多扣一次，例外不扣额度。

**这不是每周硬封锁时段。** 每周硬封锁、全天封锁、倒计时和循环仍是独立条件；任一要求封锁，仍会封锁。如果只是想“这个时段最多用30分钟”，不要另外把相同时段设为硬封锁。

## 跨午夜与重置

- 结束时间早于开始时间表示跨午夜，比如 **22:00—次日02:00，共用30分钟**。
- 这一整段共用一份额度，午夜不清零；下一天22:00进入新周期，重新获得30分钟。
- 开始时间包含在内，结束时间不包含。结束可填24:00，开始结束相同会提示错误。
- 没用完的不结转。时段外仍可能被其他规则、时间异常或未就绪的浏览器组件限制。
- 每个规则组支持一个每天重复的额度时段；需要多个独立时段额度时，可以建立不同规则组。时区使用规则当前设置，默认上海。

## 数据与修改

旧每日额度保持原来的全天计时和零点重置，不会自动改为指定时段。重启不清空已用额度。修改时段或时区不会给同一组规则制造新额度：在新周期对应账户中沿用已知用量的较大值，并保留采集缺口；调整后的首个周期可能沿用旧用量，后续按日周期重置。

指定时段不作为“剩余时间通行证”覆盖其他硬封锁。统计缺失如果与额度时段重叠，标记该周期缺口，保守限制；完全发生在时段外的缺口不会污染这份额度。空闲60秒、锁屏与睡眠维持原来的计时处理。

界面显示额度范围、本周期已用量和当前是否处于时段外。JSON保留额度时段；额度CSV新增 `current_quota_window` 当前范围说明，`local_date` 在跨午夜规则中表示该周期的开始日期。历史记录的范围说明来自当前配置，不冒充历史时段快照。

137项核心测试及界面自测通过，包括时段边界、跨午夜、零点不重置、空闲裁剪、缺口裁剪、额度耗尽、时段结束放行、多个目标不重复扣时、待生效修改继承用量、重启恢复与旧每日额度兼容。更新器继续运行Windows PowerShell 5.1的8项文件替换/恢复检查。未在用户安装中应用更新，实际主机验证由用户完成。
