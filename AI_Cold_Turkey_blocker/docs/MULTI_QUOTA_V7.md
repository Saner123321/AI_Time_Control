# 每段独立额度 v7

本版实现同一组规则内多个时间段、每段自己的额度。例如上午09:00—12:00可用20分钟，晚上18:00—22:00可用40分钟，两份额度互不占用；上午用完不会扣除晚上额度。

## 更新

先在旧窗口提交想保留的草稿，再关闭专注计划主窗口。双击本文件夹 **更新分时段额度.exe**，点击 **更新并开始30分钟测试**，完成管理员确认，再点击 **打开新版 · 设置独立额度**。此包更新已知v6主机安装。

更新保留数据库、规则、例外及备注、旧用量和待生效申请。已停用的规则保持停用；只重新安排短期测试截止和原独立恢复任务。浏览器组件不变，无需重载。安装及实际操作由用户完成。

## 设置

在规则的“何时限制”区域：

1. 勾选 **启用可用时间额度**。
2. 额度方式选择 **分时段，每段独立额度**。
3. 每行填写 **时段名称、开始、结束、额度/分钟**，点 **添加独立额度时段** 增加下一行。
4. 点击主窗口 **提交完整修改**。新增放行、提高额度、移除或变更现有时段仍按强弱判断和原延迟生效，等待时原规则继续运行。

每个规则组最多24个每天重复的时段。名称可修改，各行会显示自己的本周期已用分钟数。全天额度模式仍保留；旧版单时段设置会显示为一行，未修改时保持原表示和计时，不自动重置。

## 语义

- 各时段拥有独立的用量账户和上限；同组的应用、网站共用**当前这一时段**的额度。同一秒不因应用和网站同时命中而重复扣除。
- 本时段用完后，只封锁到本时段结束；下一时段使用它自己的额度。不结转。
- 每天对应时段开始时进入新周期。结束早于开始表示跨午夜，例如22:00—次日02:00共用30分钟，午夜不会再获得一份额度。
- 开始包含、结束不包含；相邻时段可接在同一分钟。时段不允许重叠，跨午夜部分也会检查重叠，避免重复扣时和额度冲突。
- 未设置时段内不受这些额度限制。每周硬封锁、全天封锁、倒计时、循环和其他规则仍独立生效；有剩余额度不能抵消硬封锁。
- 采集缺口只影响与缺口重叠的时段，其他时段不会被一起标成用量未知。前台使用、空闲60秒、锁屏和睡眠的计时规则保持不变。

## 用量保留

时段有稳定身份，编辑名称或限额不会清空计数。转换旧单时段到多时段时，原时段的用量继承到对应行，新增且不重叠的行不占用旧时段额度。

调整、合并时段或时区时会继承覆盖范围内已有用量和缺口，合并多个原时段会继承其合计用量。跨午夜历史无法从累计数精确拆分时，首个调整周期采用保守继承，可能比重新按新时间计算更严格；不会因改时段获得一份全新额度。正常后续周期独立重置。

用量JSON和CSV可区分时段，CSV的 `quota_slot_id` 对应各时段身份，`local_date` 为周期开始日期，当前范围说明仍来自当前配置。已移除时段的历史用量保留，不重建数据库。

151项核心测试及界面自测通过，包括各段独立扣时和额度、相邻边界、跨午夜、重叠校验、单段缺口隔离、提额延迟、旧版迁移、合并累计、重启保存和分段导出。图形界面自测确认可保存09:00—12:00的20分钟及18:00—22:00的40分钟。更新器另运行8项Windows PowerShell 5.1文件替换与恢复测试。本轮未应用主机更新或操作用户界面。
