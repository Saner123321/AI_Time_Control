# 可操作的应用封锁联调 v1（仅 VMware）

这一版把规则编辑界面接到了真正的 Windows 服务和 AppLocker。它是虚拟机测试版，尚未在来宾中验收；不提供主机安装。
旧 `AICT-desktop-preview-v1` 仍是不会封锁的模拟预览，本包与它使用不同目录和数据库，不能混用或覆盖升级。

## 本轮范围

- 选择本地 EXE，以当前文件版本的 PE SIP SHA256 身份登记；按每周时段、跨午夜、固定循环或全天规则封锁。
- AppLocker 拒绝新启动；服务另行识别、结束已经运行的选中应用。仅处理指定用户，不靠程序名称判断。
- 后台保存完整修改并决定延迟和锁定。关闭界面、改草稿或撤销待生效修改都不能直接删除现行规则。
- 界面分别显示保存结果和系统策略读回结果。后台失联时显示未知，不显示“已经解除”。
- SQLite 持久保存规则、应用身份、循环起点和冻结修改。同一次 Windows 开机内服务恢复可继续计时；系统开机标识变化时保守拒绝修改，需要故障恢复。本轮不做重启实验。
- 导出规则 JSON、已有额度表 CSV；未连接真实用量，空记录不代表使用为零。

网站、浏览器插件、防移除插件兜底、真实使用额度、应用白名单、Store/MSIX、正常产品卸载/更新尚未接入。
对应界面功能禁用，后台同样拒绝这些配置，不能用它们进行实际自控。
默认测试参数为循环封锁 **2分钟、休息1分钟**，后续修改延迟 **1分钟**，不是原完整产品计划的24小时默认。

## 在虚拟机运行

使用已有 `AICT-phase0-baseline` 快照作为恢复参考。本轮不要求重新恢复快照、创建快照或重启。
先确认上一轮联调的服务和策略已清理；若存在其他 AppLocker 策略，本包会拒绝覆盖。

把 `AICT-interactive-lab-v1.zip` 复制到虚拟机桌面，解压为桌面的 `AICT-interactive-lab-v1` 文件夹。
在**虚拟机**的管理员 Windows PowerShell 5.1 中，从桌面运行：

```powershell
.\AICT-interactive-lab-v1\scripts\Install-InteractiveLab.ps1 -SnapshotReference 'AICT-phase0-baseline'
```

参数只记录已有快照名称，不会调用 VMware 或执行恢复。软件自带 .NET 运行时，不要求安装 SDK，不修改全局脚本执行策略。
AppIDSvc 必须已经运行；本包不修改它的启动配置。如果被拒绝，保留错误，不通过修改主机来解决。

安装过程先以普通权限自动检查两个自带无害样本：原本可启动、现有窗口被结束、受限身份新启动失败、不同内容对照仍允许、锁定中关闭规则被冻结、窗口结束后冻结修改生效、样本重新可启动。
还检查客户端不能注入时间或发送任意停止服务命令。失败时保留证据并尝试撤销本次服务和策略，不会假装安装通过。
这些检查只操作本包样本，不针对其他应用。自动检查成功后才打开可操作的界面。

## 手动体验（约数分钟）

1. 点击“打开无害测试应用”，看到测试窗口。新规则点击“选择 EXE…”，默认已指向该测试应用；确认选中它。
2. 保持默认的2分钟/1分钟循环，点击“提交完整修改”，确认强制结束提示。观察测试窗口结束、左侧出现系统策略确认；再点击打开测试应用，应被拒绝。
3. 关闭界面或用任务管理器结束 **Aict.Desktop**，再运行下面的打开命令。现行规则和原循环起点应保留，关闭界面本身不能解锁。
4. 封锁期间取消勾选“启用此规则”并提交。它应成为一份固定的待生效修改；等待结束且旧规则进入允许修改的休息窗口后才解除。等待期间不能替换这份内容；撤销只保留旧规则。
5. 如要尝试结束后台服务，先在界面确认封锁已经执行。记录是普通还是已提权任务管理器、操作是否被拒绝、后台多久恢复、规则是否仍在。AppLocker 已执行的限制独立于界面和服务进程；本包没有“管理员永远杀不掉”的承诺。

```powershell
.\AICT-interactive-lab-v1\scripts\Open-InteractiveLab.ps1
```

首次只用无害样本。对真实应用启用后会强制结束匹配进程，可能丢失未保存内容；界面提交时也会明确提示。
本轮不需要主动关闭电脑或恢复快照。程序更新会改变哈希，需要在可修改时重新登记该版本。

## 回传与解除实验

尝试后收集当前状态：

```powershell
.\AICT-interactive-lab-v1\scripts\Collect-InteractiveLab.ps1
```

把输出的整个 `interactive-session-时间戳` 文件夹复制回主机项目的 `reports` 目录，再提供路径。
文件夹含来源清单哈希、安装/收集结果、自动样本检查、当前后台状态和可观察到的进程结束事件。
也请简述手动做过的动作和结果；自动检查不会替你授予任务管理器、真实界面或插件测试通过状态。
这是试验记录，尚未实现完整产品的90天日志、用量采集或全部违规尝试记录。

完成或遇到问题时，在虚拟机管理员终端运行独立恢复：

```powershell
.\AICT-interactive-lab-v1\scripts\Recover-InteractiveLab.ps1
```

恢复只撤销本轮所有权匹配的服务、策略及任务，保留规则文件和证据，不递归删除数据，不覆盖其他工具的策略。
恢复后窗口可能仍开着并显示连接中断，可正常关闭。该管理员恢复是明确的实验救援入口，不是普通界面的解除按钮。
本包设 **60分钟自动撤销**；若意外重启，另有启动后5分钟的清理任务。这是限制实验持续时间的保护，不是产品的锁定保证。
无需为了触发清理而重启。若恢复报错，不删除目录或自行清空系统策略，回传证据排查。

## 实现与验证边界

- 命名管道验证调用用户和服务身份；普通界面只提交固定类型的配置与哈希元数据，不传系统命令或任意服务端文件路径。
- 服务读取进程映像时模拟该进程用户，确认指定 SID 和 SIP 哈希后，使用同一个持有的进程句柄结束并等待退出。不能识别、无权读取的进程不会按名称误杀；这也意味着这些场景未承诺覆盖。
- 必需系统程序、命令恢复工具和本包服务/界面身份不能登记为限制。拒绝规则仅针对指定用户；允许规则补齐 EXE 集合默认允许语义。
- 原生桥逐项校验自有 XML，拒绝其他规则或策略冲突。规则集合切换目前使用删除/创建，可能有短暂窗口，尚未宣称原子切换或达到2秒指标。
- 当前后台每轮启动独立 Framework/MI 桥读回，开销和切换时延需来宾实测；后续按测量优化。
- 服务恢复由 Windows SCM 配置，普通权限不能通过界面停止它；提权管理员仍可能绕过。此次不修改现有账户结构、不禁用任务管理器。
- 本机已验证纯规则/存储/协议、编译、预览窗口渲染和主机拒绝保护。**实际来宾安装、任意选中应用、退出/结束进程以及新版恢复都仍待回传证据确认。**
